Glisk renderer decision report

Which renderer should power a live HTML pager inside Ghostty? This report compares the v0 candidates and records the evidence needed before the viewer is built around one engine.

Decision report Ghostty 1.4+ macOS No JavaScript

Summary

Recommended path

Blitz with the Vello CPU rasterizer keeps the document model and the renderer in one Rust process. That is the only candidate that can preserve disclosure and focus state while reflowing on terminal resize.

One

Viewport-sized image

The terminal receives one Kitty image placement per redraw. The raster stays at viewport size even when the document is many screens tall.

Offline

Resource policy

The document gets its own HTML and embedded assets. Network fetches, secondary files, and navigation away from the document are denied before layout.

Decision: continue with Blitz + Vello CPU only if the pinned build renders the cards, the headered table, and the inline SVG chart at both tested widths and survives keyboard interaction and resize. The measurements below are the comparison baseline.

Evidence

Evidence 1: how the renderer was exercised

The pinned prototype loads this same file with external fetches denied. It resolves layout at a narrow CSS viewport and at a wide CSS viewport, paints each viewport with Vello CPU, and writes a PNG frame before sending it to the terminal.

  • Keyboard: Tab and Shift+Tab move focus; Enter follows a fragment link or toggles the focused disclosure.
  • Resize: geometry is measured again, the viewport is re-laid out, and the reading position, focus, and open disclosures are kept.
  • Exit: the image is deleted, raw mode is disabled, and the alternate screen is left before the shell prompt returns.

Any value not observed in a live Ghostty run is marked unverified in the spike notes instead of being estimated as measured.

Evidence 2: known gaps and resolution conditions

Blitz has no JavaScript and supports only part of the table and overflow model. The report therefore uses flex-wrapped cards, a fixed-layout table, and an inline SVG chart rather than scripted widgets or sticky headers.

  • If the headered table paints without header text, the acceptance condition is a pinned Blitz build that paints table headers, or a documented CSS fallback using grid rows.
  • If a narrow viewport clips the table, the condition is a verified alternate layout at the narrow width, not a horizontal scroll assumption.
  • If foreground input or resize replies cannot be separated from keys, the condition is a single owner that buffers replies and keys with a shared deadline.

Risks

Rasterized text

Terminal selection and screen readers cannot read an image. Search and a plain-text mode must use the same document walk that produces the report text.

Geometry

Cell pixels differ by display scale. Measure cell geometry on the target and derive CSS size from measured pixels rather than assuming a Retina factor.

Payload growth

Keep the raster viewport-sized, cap the encoded frame, and replace one image ID instead of accumulating placements.
