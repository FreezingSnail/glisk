Live reload with stable ids

Open a copy of this file, keep Glisk in one pane, and save from another. Glisk follows the named file by default; --no-watch holds the revision it opened.

Why the ids matter

On reload Glisk restores the visible block or its containing section by id, then a surviving preceding heading, then the previous scroll offset. Open disclosure ids, focused controls, and the search query are mapped onto the new document.

RevisionReplace this line when you edit the copy. The id should stay the same.
AnchorKeep id="reload-anchor" on the block you are reading.
DisclosureKeep id="reload-details" open across the save.
Reload checklist
  • Copy this example to a working file: cp examples/tour/reload.html reload-demo.html.
  • Open it: glisk reload-demo.html.
  • Edit a paragraph and save. The status row briefly shows the reload result and the reading position stays anchored.
  • Try an invalid save. The last good report stays on screen with a concise reload message.
  • Open a second session with --no-watch and confirm a save does not repaint it.

Same behavior in tmux

In one supported tmux pane, opt in with tmux set-option -p allow-passthrough on and run Glisk there. Save or atomically regenerate the same path from another pane. Glisk rechecks the pane and re-uploads its latest frame after the pane returns to view.
